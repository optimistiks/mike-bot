# Score plain groups too, and leave the upgrade unhandled

ADR-0016 confined Mike-bot to supergroups on the reasoning that every Chat it serves is one, so a plain group is history it will never have. v1 scored in either kind, and confining v2 means a group that Telegram has not upgraded — small, quiet, or simply new — gets nothing from the bot it was added to, with no signal saying why. So `group` joins `supergroup` as a Chat Mike-bot serves: Messages are cached, Display identities written, Marks placed, and the Stats command answered exactly as in a supergroup.

Private chats and channels stay out. Neither can hold a Mark — an Actor cannot mark their own Message and a bot is never a Subject — so admitting them buys no scoring. A private chat would additionally cost something: `/stats` there would write a Registration against a positive chat id with no Chat metadata behind it, which the Mini App's chat list renders as a bare `Чат 12345` leading to an empty Leaderboard.

The predicate ADR-0016 deleted comes back as `isScorableChatType`, because the check is now two-valued and an inline `type === "group" || type === "supergroup"` repeated at five call sites states the rule five times rather than once.

What ADR-0016 called impossible is now merely unhandled. A scored group that Telegram upgrades to a supergroup keeps its Marks, Message authors, Display identities, and Registrations under the dead id, and the new Chat starts empty; the `migrate_to_chat_id` branch still writes nothing, and now logs a skip saying so. This is accepted rather than solved: the event happens at most once per Chat, and the repair is a one-time move of rows between two known ids, which is cheaper to write when it is actually needed than to carry — and to keep correct against every table added meanwhile — for an event that may never arrive. The trap is real: until that move is run, the upgraded Chat's Leaderboards read zero and nothing in Telegram says the history exists. Watch for `skip chat upgrade` in the logs; it is the only warning there will be.
